# EduDocu 시스템 구조와 사용 규칙

> 한 줄 요약: **구글 시트 = 서버(원본)**, **PC·휴대폰 = 창문**, **GitHub = 매일 찍는 사진(백업)**

## 1. 역할

| 구분 | 역할 | 들어 있는 것 |
|---|---|---|
| 구글 시트 (구글 드라이브) | **서버, 원본** | schools, students, curricula, class_dates, doc_records 시트 |
| AppSheet (데스크탑·노트북·휴대폰) | **입력·조회 화면** | 데이터 없음. 원본을 열어 보는 창 |
| GitHub `snapshots/` | **백업** | 매일 새벽 4시쯤 원본을 JSON으로 저장 (`snapshot_날짜.json`) |

```
 데스크탑 ─┐
 노트북  ──┼──▶  구글 시트(원본)  ──매일 새벽──▶  GitHub snapshots/ (백업)
 휴대폰  ─┘        ▲
                   └─ 실수했을 때: 버전 기록 또는 백업으로 되돌리기
```

예: 데스크탑에서 「호암초 수강료 6,250 → 7,000」으로 고치면 구글 시트에 저장되고,
노트북 AppSheet를 열면 바로 7,000이 보입니다. 데스크탑이 꺼져 있어도 상관없습니다.

## 2. 지켜야 할 규칙 3가지

1. **원본(구글 시트·AppSheet)에서만 고친다.**
   내려받은 `.xlsx`, `snapshots/*.json`, 생성된 서류 파일을 고쳐도 원본에는 반영되지 않습니다.
   PC에 있는 엑셀 파일을 기준으로 작업하는 스크립트도 같은 이유로 원본과 어긋날 수 있습니다.
2. **기기를 바꾸기 전에 동기화 대기 숫자가 0인지 확인한다.**
   AppSheet 상단의 동기화 아이콘 숫자가 0이어야 모든 변경이 서버에 올라간 것입니다.
3. **같은 행을 두 기기에서 동시에 고치지 않는다.** 나중에 저장한 쪽이 덮어씁니다.

## 3. AppSheet 동기화 설정 체크리스트 (한 번만)

AppSheet 에디터 → **Settings → Offline / Sync** 에서:

- [ ] `Sync on start` **켜기**: 앱을 열 때 최신 데이터를 받아옴
- [ ] `Automatic updates` **켜기**: 수정하면 곧바로 서버에 올라감
- [ ] `Delayed sync` **끄기**: 켜져 있으면 변경이 기기에 쌓였다가 늦게 올라감
- [ ] 저장 후 **Save** 버튼을 누르고, 데스크탑·노트북 앱을 한 번씩 껐다 켜기

확인 테스트: 노트북에서 테스트 학생 1명 추가 → 데스크탑에서 새로고침 → 보이면 정상 → 테스트 학생 삭제.

## 4. 되돌리는 방법

| 상황 | 방법 |
|---|---|
| 방금(몇 분~며칠 전) 실수 | 구글 시트 **파일 → 버전 기록 → 버전 기록 보기**에서 원하는 시점 복원 |
| 특정 날짜 상태로 통째 복구 | 아래 복구 도구로 CSV를 만든 뒤 해당 시트에 가져오기 |

복구 도구 사용 예:

```bash
python3 tools/restore_snapshot.py                        # 가장 최근 백업 → restore_<날짜>/*.csv
python3 tools/restore_snapshot.py 2026-10-15 --only students   # 10/15 학생 시트만
```

만들어진 `students.csv`를 구글 시트 students 탭에서
**파일 → 가져오기 → 업로드 → "현재 시트 바꾸기"**로 올리면 그 날짜 상태가 됩니다.
(복구 전에 버전 기록에 현재 상태가 남아 있으니 되돌리기도 가능합니다.)

## 5. 백업이 멈췄을 때

`.github/workflows/backup-check.yml` 이 매일 오전 10시에 최신 백업 날짜를 확인합니다.
2일 이상 새 백업이 없으면 GitHub 이슈 **"⚠️ 자동 백업(snapshot)이 멈췄습니다"** 를 1개만 만들고,
백업이 다시 들어오면 자동으로 닫습니다. (이 감시는 main 브랜치에 합쳐져야 동작합니다.)

확인 순서:
1. 구글 시트 → **확장 프로그램 → Apps Script** → 왼쪽 **트리거(시계 아이콘)**:
   매일 실행 트리거가 있는지, **실행 기록**에 실패가 있는지 확인
2. 실패 메시지가 인증/토큰 관련이면 GitHub 토큰 만료가 흔한 원인 → 새 토큰을 발급해
   스크립트 속성(Script Properties)에 다시 저장
3. 트리거를 새로 만들 때는 **기존 트리거를 지운 뒤** 1개만 만들 것 (중복 실행 방지)
